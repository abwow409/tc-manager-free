TrinityCore セキュアアカウント管理システム – システムドキュメント

1. システム概要
本システムは、TrinityCore（World of Warcraft エミュレーター）向けの Web ベースのアカウントセキュリティおよび管理プラットフォームです。Battle.net アカウント体系をサポートし、登録、アクティベーション、ログイン、パスワード復元、セキュリティ設定、ポイントチャージ、ポイントショップなどの完全な機能を提供します。このシステムは TrinityCore の auth、characters、world データベースと深く統合され、SOAP インターフェースを介してゲームサーバーと通信し、アカウント、キャラクター、アイテムなどをオンラインで管理できます。

PHP 8+ で開発され、MVC 階層構造に従い、堅牢なセキュリティメカニズム（CSRF、セッションフィクセーション防止、IP ブラックリスト、レート制限、監査ログ、パスワード強度など）を内蔵しています。さらに 多言語（中国語、英語、フランス語、ロシア語など）および 複数の決済ゲートウェイ（Stripe、YiPay など）をサポートしており、中小規模のプライベート WoW サーバーの運営に適しています。

3. 主要機能モジュール

3.1 アカウント登録とアクティベーション

登録フロー: ユーザーがメールとパスワードを入力 → システムが SOAP bnetaccount create を呼び出して Battle.net アカウントを作成 → 自動的にゲームアカウント（account テーブル）と関連付け、email フィールドを保存 → アクティベーショントークンを生成（有効期限 24 時間）→ SMTP でアクティベーションメールを送信。

アクティベーションメカニズム: ユーザーがメール内のリンクをクリック → トークンの有効性を検証 → 一時保存されたパスワードハッシュを account.passwd に書き込み → トークンを使用済みにし、アカウントが正式に有効化。

3.2 ログインとセッション管理

ログイン: メール + パスワード（SHA1 検証、TrinityCore の sha_pass_hash または passwd フィールドと互換）。

記憶する: remember_me_tokens テーブルに基づき、30 日間自動更新。

セッションセキュリティ: ログインごとに一意のセッション ID を生成し、IP、User‑Agent、最終アクティビティ時刻を記録；他のデバイスのセッション表示および取り消しをサポート。

アカウントロック: 連続ログイン失敗回数がしきい値（デフォルト 5 回）を超えると 30 分間ロック。

3.3 パスワード復元とリセット

方法 1: 登録メールにリセットリンクを送信（有効期限 60 分、使い切り）。

方法 2: 事前設定されたセキュリティ質問（最低 3 つ）で本人確認後、直接新しいパスワードを設定。

どちらの方法も SOAP bnetaccount set password を呼び出してパスワードを更新し、account.passwd も同期。

3.4 セキュリティ設定ページ

パスワード変更: 現在のパスワード確認後、SOAP で更新。

アクティブセッション管理: ログイン中の全デバイスを表示し、個別セッションまたは現在以外の全セッションを終了可能。

セキュリティ質問設定: ユーザーが 3〜5 個のカスタム質問と回答（ハッシュ保存）を設定し、パスワード復元の補助手段とする。

3.5 ユーザープロフィールとキャラクター情報

Battle.net アカウント情報、GM レベル、関連ゲームアカウント一覧を表示。

characters データベースに接続し、全キャラクター（名前、種族、クラス、レベル、ゴールド、マップ、オンライン状態、総オンライン時間など）を表示。

「Unstuck」機能を提供：キャラクターを種族/クラスの初期開始地点にテレポート（データベース座標を直接更新、SOAP 不使用）。

3.6 ポイント（クレジット）システム

ポイント取得方法:

オンライン時間（totaltime フィールド）の交換 – 時間あたりのポイントを設定可能、最低交換時間あり。

チャージによる購入（次のセクション参照）。

ポイント消費方法:

アイテム交換: points_shop_items テーブルから商品（アイテム ID、数量、価格）を読み取り、指定キャラクターにゲーム内メールで送信。

レベルアップ: キャラクターを設定された目標レベル（例：90）まで直接上昇。キャラクターはオフライン必須。

ゴールドチャージ: キャラクターに指定量のゴールド（銅貨単位、オーバーフロー防止）を追加。

GM 権限交換: ゲームアカウントに GM レベル 1 を付与（account_access テーブル、RealmID = -1 で全領域有効）。

すべての取引は points_transactions テーブルにステータス（pending/success/failed）と共に記録。

3.7 ポイントチャージ（決済連携）

設定ベース: config.php で各ゲートウェイを有効化・設定。

サポートゲートウェイ:

Stripe: PaymentIntent フローを使用、フロントエンドで Stripe Elements をレンダリング、バックエンドで決済確認後自動ポイント追加。

YiPay（統合決済）: 署名生成後、決済プラットフォームにリダイレクト、非同期コールバック（notify）と同期リターン（return）を処理。

レート制御: 各ゲートウェイに独立した為替レートを設定可能（1 CNY = X ポイント）、グローバルデフォルトは 100。

セキュリティ: 全決済コールバックは署名を検証し、注文とユーザーの一致を確認して偽造を防止。

3.8 監査とロギング

監査ログ: 重要な操作（ログイン、登録、パスワード変更、商品交換、セッション取り消しなど）を audit_logs テーブルに IP、User‑Agent、詳細 JSON とともに記録。

ログインログ: 各ログイン試行（成功/失敗）を個別に記録し、セキュリティ分析に活用。

レート制限: IP および操作タイプ（登録、パスワードリセットなど）に基づき、ブルートフォース攻撃を防止。

4. 詳細セキュリティメカニズム

保護レイヤー	具体的な措置
トランスポート層	HTTPS 強制（設定可能）で中間者攻撃を防止。
認証	パスワードは SHA1（TrinityCore ネイティブ互換）または SRP6 でハッシュ；2FA 用インターフェース予約。
セッションセキュリティ	セッション ID を定期的に再生成；IP および User‑Agent にバインド；HttpOnly、SameSite=Strict クッキー；データベース永続化、有効期限および強制ログアウトをサポート。
CSRF 保護	全フォームにランダムトークン（Security::generateCSRFToken）を埋め込み、送信時に検証。
入力フィルタリング	出力時に htmlspecialchars でエスケープ；SQL クエリはプリペアドステートメント（mysqli）を使用。
パスワード強度	最低 8 文字、大小文字・数字・特殊文字を含むことを強制；脆弱パスワードのブラックリスト内蔵。
レート制限	RateLimiter が Redis またはデータベース記録を使用し、登録・パスワードリセットなどを制限（デフォルト 1 時間あたり 5 回）。
IP ブラックリスト	繰り返し違反（例：パスワード誤り 10 回超）の IP を自動ブラックリスト追加、有効期限設定可能。
ログイン保護	失敗回数超過でアカウントを 30 分ロックし、ブルートフォースを防止。
アクティベーションメカニズム	登録後、Web パネルへのログインにはメールアクティベーションが必須；アクティベーショントークンは使い切り、24 時間有効。
アクセス制御	制限ページ（プロフィール、ショップなど）はすべてセッション有効性をチェックし、未認証ユーザーはリダイレクト。
監査証跡	すべてのセンシティブ操作を audit_logs に記録し、事後追跡を可能にする。
SOAP 通信	worldserver との通信には独立した資格情報（ユーザー名/パスワード）を使用し、TLS を推奨。

6. 設定説明（config.php）
設定ファイルは以下の主要セクションで構成されます。

6.1 データベース接続（database / characters_database / world_database）

それぞれ auth、characters、world データベースに接続し、独立したホストとポートをサポート。

6.2 SOAP 設定

php
$config['soap'] = [
    'host' => '127.0.0.1',      // worldserver SOAP アドレス
    'port' => 7878,             // デフォルトポート
    'username' => '3#1',        // 形式 `account_id#realm_id`
    'password' => '...',        // SOAP パスワード（worldserver.conf と一致）
    'timeout' => 30,
    'debug' => false,
];
6.3 決済ゲートウェイ（stripe / yipay / paypal / wechat / alipay）

各ゲートウェイに個別の有効化スイッチ、キー、為替レート、環境（サンドボックス）を持ちます。

YiPay は MD5 署名をサポート。

6.4 メールサービス

SMTP を使用してアクティベーション、パスワードリセット、セキュリティアラートなどのメールを送信。

Gmail、QQ メールなどに対応（アプリ固有パスワードが必要）。

6.5 セキュリティパラメータ

min_password_length、max_login_attempts、lockout_duration_minutes、session_lifetime、remember_me_lifetime など。

reCAPTCHA、2FA（予約）の有効/無効。

6.6 ポイントとショップ

points_per_hour（オンライン時間交換レート）、min_exchange_hours。

level_boost_target（レベルアップ目標値）。

商品カテゴリ：level_boost、gold、gm_level、通常アイテム。

7. デプロイ環境要件

7.1 サーバー環境

PHP: バージョン 8.2（無償版は正確に 8.2 が必要）

MySQL: 8.0+ / MariaDB 12+

Web サーバー: Apache / Nginx

必須 PHP 拡張: mysqli、session、curl、soap（必須）、gd、json、mbstring、gmp、sg11、Imagick

Composer: 2.0+

依存関係のインストール:

bash
composer require phpmailer/phpmailer
composer require stripe/stripe-php   # Stripe 利用時
7.2 TrinityCore 設定

worldserver.conf で SOAP を有効化:

text
SOAP.Enabled = 1
SOAP.Port = 7878
SOAP.Redirect = 0
auth データベースに battlenet_accounts テーブルが存在すること（TrinityCore 標準提供）。

account テーブルに email フィールドがあること（ない場合はシステムが自動追加）。

7.3 依存関係のインストール
上記の Composer コマンドを使用。

7.4 ファイル権限

config/config.php は 600 または 640（読み取り専用）を推奨。

ログディレクトリ（データベース監査を使用しない場合）は書き込み権限が必要。

アップロードディレクトリ（存在する場合）は適切なアクセス制御が必要。

7.5 ネットワークとセキュリティ

HTTPS の有効化を強く推奨（config で require_https = true に設定）。

ファイアウォールで 80/443 ポートのみを開放し、SOAP ポート（7878）は localhost に制限。

PHP および拡張機能を定期的に更新。

8. 利用フロー例

8.1 新規ユーザー登録

/register.php にアクセスし、メールとパスワードを入力。

システムが SOAP を呼び出して Battle.net アカウントを作成し、ゲームアカウントを生成してアクティベーションメールを送信。

ユーザーがメール内のアクティベーションリンクをクリック → アカウントが有効化され、Web パネルにログイン可能に。

8.2 ログインとポイント取得

/login.php にアクセスし、メールとパスワードを入力、「記憶する」を選択可能。

ログイン後、/profile.php でキャラクター一覧と現在のポイントを確認。

「ポイントセンター」セクションでオンライン時間（時間）を入力し、ポイントに交換（キャラクターの totaltime を消費）。

8.3 ポイント消費

「ポイントショップ」をクリックして /points_shop.php へ。

商品一覧（アイテム、レベルアップ、ゴールド、GM 権限）を閲覧。

商品と対象キャラクターを選択し「交換」をクリック。

システムがポイントを差し引き、該当アクション（アイテムメール送信、レベル更新、ゴールド追加など）を実行し、取引を記録。

8.4 ポイントチャージ

/topup.php にアクセスし、チャージ金額を入力。

決済方法を選択（Stripe/YiPay など）。

決済完了後、システムが自動的にポイントをアカウントに追加。

8.5 セキュリティ設定

/security_settings.php でパスワード変更、セッション管理、セキュリティ質問を設定。

セキュリティ質問はパスワード復元時の代替認証手段として使用。

9. 拡張とカスタマイズ

新しい決済ゲートウェイの追加: config.php に設定を追加し、topup.php でルーティングとコールバック処理を実装。

新しい商品タイプの追加: points_shop.php の交換ロジックに新しい category 分岐を追加。

多言語: languages/ ディレクトリに対応言語ファイルを追加し、Language クラスを継承。

2FA: システムは既に user_2fa テーブルとインターフェース予約を用意しているため、TOTP ライブラリ（例：robthree/twofactorauth）を統合して有効化可能。

10. メンテナンスと監視

ログ表示: audit_logs および login_logs テーブルで詳細な操作履歴を確認でき、管理インターフェース（別途開発）で表示可能。

定期クリーンアップ: システムに AuditLogger::cleanOldLogs($days) 関数が組み込まれており、古いログを定期的に削除できる。

データベース管理: セッションやトークン関連テーブルで期限切れレコードを定期的に削除し最適化することを推奨。

セキュリティ更新: PHP および Composer 依存関係のセキュリティパッチを定期的に適用。

11. よくある質問（FAQ）

Q: 登録時に「SOAP service unavailable」エラーが発生します。
A: worldserver が実行中か、SOAP 設定が正しいか、ファイアウォールで 7878 ポートが許可されているか（ローカルアクセス推奨）を確認してください。

Q: アクティベーションメールが届きません。
A: SMTP 設定を確認し、メールログを調べてください。ユーザーは「アクティベーションメール再送信」機能を使用できます。

Q: ログイン後、キャラクターが表示されません。
A: characters_database 設定が正しいか、その Battle.net アカウントに実際にキャラクターが存在するかを確認してください。

Q: ポイントでアイテムを交換したが受け取れません。
A: characters データベースの mail および item_instance テーブルが正しく挿入されているか、キャラクターのメールボックスが満杯でないかを確認してください。

Q: パスワードリセットが失敗します。
A: SOAP が利用可能でアカウントが存在することを確認してください。セキュリティ質問を使用する場合、回答ハッシュが一致するか（大文字小文字区別）を確認してください。

12. バージョンとサポート

現行バージョン: TrinityCore 12.x ベース（11.0 Dragonflight および以前のバージョンをサポート）。

互換性: Battle.net アカウント体系を使用するすべての TrinityCore ブランチと理論上互換（一部フィールド名の調整が必要な場合あり）。

テクニカルサポート: TrinityCore 公式フォーラムまたは本ドキュメントを参照し、具体的なエラーログに基づいてトラブルシューティングを行ってください。
