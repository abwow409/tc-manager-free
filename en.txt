TrinityCore Secure Account Management System – System Documentation

1. System Overview
This system is a web-based account security and management platform designed for TrinityCore (World of Warcraft emulator). It supports the Battle.net account system and provides full-featured functionality including registration, activation, login, password recovery, security settings, point (credit) top‑up, and a points shop. The system deeply integrates with TrinityCore’s auth, characters, and world databases and communicates with the game server via the SOAP interface, enabling online management of accounts, characters, items, and more.

Developed with PHP 8+, it follows an MVC architectural pattern and incorporates robust security mechanisms (CSRF protection, session fixation prevention, IP blacklisting, rate limiting, audit logging, password strength enforcement, etc.). It also supports multiple languages (Chinese, English, French, Russian, etc.) and multiple payment gateways (Stripe, YiPay, etc.), making it suitable for small‑to‑medium private WoW server operations.

3. Main Functional Modules

3.1 Account Registration & Activation

Registration flow: User fills in email and password → system calls SOAP bnetaccount create to create a Battle.net account → system automatically links the game account (in the account table) and stores the email field → generates an activation token (valid for 24 hours) → sends an activation email via SMTP.

Activation mechanism: User clicks the link in the email → token validity is verified → the temporarily stored password hash is written to account.passwd → token is marked as used, and the account is officially enabled.

3.2 Login & Session Management

Login: Supports email + password (SHA1 verification, compatible with TrinityCore’s sha_pass_hash or passwd field).

Remember‑me: Based on the remember_me_tokens table, automatically renews for 30 days.

Session security: Each login generates a unique session ID, recording IP, User‑Agent, last activity time; supports viewing and revoking sessions on other devices.

Account lockout: After a configurable number of consecutive failed login attempts (default 5), the account is locked for 30 minutes.

3.3 Password Recovery & Reset

Method 1: Receive a reset link via the registered email (valid for 60 minutes, one‑time use).

Method 2: Authenticate via pre‑set security questions (at least 3) and directly set a new password.

Both methods call SOAP bnetaccount set password to update the password and simultaneously update account.passwd.

3.4 Security Settings Page

Change password: Requires verification of the current password, updates via SOAP.

Manage active sessions: Lists all logged‑in devices; supports single device logout or logging out all devices except the current one.

Set security questions: Users can define 3‑5 custom questions and answers (hashed) for auxiliary password recovery.

3.5 User Profile & Character Information

Displays Battle.net account info, GM level, and associated game account list.

Connects to the characters database to display all characters (name, race, class, level, money, map, online status, total online time, etc.).

Provides an “Unstuck” function: teleports the character to the race/class starting location (updates coordinates directly in the database, no SOAP required).

3.6 Points (Credit) System

Earning points:

Exchange online time (from the totaltime field) – configurable points per hour, with a minimum exchangeable hours requirement.

Purchase via top‑up (see next section).

Spending points:

Item exchange: Reads items from points_shop_items (item ID, quantity, price) and sends them via in‑game mail to the selected character.

Level boost: Directly raises the character to a configured target level (e.g., 90), requires the character to be offline.

Gold purchase: Adds a specified amount of gold (in copper, with overflow protection) to the character.

GM permission purchase: Grants GM level 1 to the game account via account_access (RealmID = -1 for all realms).

All transactions are recorded in the points_transactions table with status tracking (pending/success/failed).

3.7 Points Top‑Up (Payment Integration)

Configuration‑driven: Enable and configure each gateway in config.php.

Supported gateways:

Stripe: Uses PaymentIntent flow, frontend renders Stripe Elements, backend confirms the payment and automatically adds points.

YiPay (aggregated payment): Generates a signature, redirects to the payment platform, and handles asynchronous callbacks (notify) and synchronous returns (return).

Rate control: Each gateway can have its own exchange rate (1 CNY = X points), with a global default of 100.

Security: All payment callbacks verify signatures and check that the order matches the user, preventing forgery.

3.8 Auditing & Logging

Audit logs: Records critical operations (login, registration, password change, item exchange, session revocation, etc.) in the audit_logs table, including IP, User‑Agent, and JSON details.

Login logs: Separately records every login attempt (success/failure) for security analysis.

Rate limiting: Based on IP and operation type (e.g., registration, password reset) to prevent brute‑force attacks.

4. Detailed Security Mechanisms

Protection Layer	Specific Measures
Transport Layer	Forces HTTPS (configurable) to prevent MITM attacks.
Authentication	Passwords hashed with SHA1 (compatible with TrinityCore native) or SRP6; reserved interface for 2FA.
Session Security	Session ID regenerated periodically; bound to IP and User‑Agent; HttpOnly, SameSite=Strict cookies; session persistence in DB, supports expiry and forced logout.
CSRF Protection	Every form embeds a random token (Security::generateCSRFToken) verified on submission.
Input Filtering	Output escaped with htmlspecialchars; SQL queries use prepared statements (mysqli).
Password Strength	Enforces at least 8 characters, containing uppercase, lowercase, digits, and special characters; built‑in weak password blacklist.
Rate Limiting	RateLimiter uses Redis or database records to limit registration, password reset, etc. (default 5 per hour).
IP Blacklist	Automatically blacklists IPs that repeatedly violate (e.g., >10 password errors), with configurable expiry.
Login Protection	Account lockout after too many failed attempts (30 minutes) to prevent brute force.
Activation Mechanism	Accounts must be activated via email before web panel login; activation token is one‑time and valid for 24 hours.
Access Control	All restricted pages (profile, points_shop, etc.) check session validity and redirect unauthenticated users.
Audit Trail	All sensitive operations logged to audit_logs for later investigation.
SOAP Communication	Uses separate credentials (username/password) to communicate with worldserver; TLS recommended.
5. Database Design (Extension Tables)
In addition to TrinityCore’s native tables, the system adds the following tables (see auth.sql):

Table Name	Purpose
account_activation_tokens	Stores registration activation tokens (with temporary password hash)
password_reset_tokens	Stores password reset tokens (one‑time, valid for 60 minutes)
password_reset_limits	Records IP/user password reset request counts (for rate limiting)
user_security_questions	Stores user security questions (question ID and answer hash)
user_2fa	Stores TOTP secret keys (reserved)
remember_me_tokens	Remember‑me tokens (persistent login)
account_sessions	Active session records (for multi‑device management)
login_logs	Login attempt logs
audit_logs	Audit logs (JSON details)
rate_limits	General rate‑limiting records
ip_blacklist	IP blacklist (with expiration)
user_points	User point balance and statistics
points_shop_items	Shop item configuration (item ID, price, stock, category, etc.)
points_transactions	Points transaction records (exchanges, top‑ups, time exchanges)
6. Configuration Instructions (config.php)
The configuration file contains the following major sections:

6.1 Database Connections (database / characters_database / world_database)

Connects to auth, characters, and world databases respectively, supporting separate hosts and ports.

6.2 SOAP Configuration

php
$config['soap'] = [
    'host' => '127.0.0.1',      // worldserver SOAP address
    'port' => 7878,             // default port
    'username' => '3#1',        // format `account_id#realm_id`
    'password' => '...',        // SOAP password (matches worldserver.conf)
    'timeout' => 30,
    'debug' => false,
];
6.3 Payment Gateways (stripe / yipay / paypal / wechat / alipay)

Each gateway has independent enable switch, keys, exchange rate, and environment (sandbox).

YiPay supports MD5 signing.

6.4 Email Service

Uses SMTP to send activation, password reset, security alert emails.

Supports Gmail, QQ Mail, etc. (requires app‑specific passwords).

6.5 Security Parameters

min_password_length, max_login_attempts, lockout_duration_minutes, session_lifetime, remember_me_lifetime, etc.

Enable/disable reCAPTCHA, 2FA (reserved).

6.6 Points & Shop

points_per_hour (online time exchange rate), min_exchange_hours.

level_boost_target (target level for boosts).

Shop item categories: level_boost, gold, gm_level, regular items.

7. Deployment Environment Requirements

7.1 Server Environment

PHP: Version 8.2 (the free version requires exactly 8.2)

MySQL: 8.0+ / MariaDB 12+

Web Server: Apache / Nginx

PHP Extensions required: mysqli, session, curl, soap (mandatory), gd, json, mbstring, gmp, sg11, Imagick

Composer: 2.0+

Install dependencies:

bash
composer require phpmailer/phpmailer
composer require stripe/stripe-php   # if Stripe is enabled
7.2 TrinityCore Configuration

worldserver.conf must enable SOAP:

text
SOAP.Enabled = 1
SOAP.Port = 7878
SOAP.Redirect = 0
The auth database must have the battlenet_accounts table (provided by TrinityCore).

The account table must include an email field (the system will add it automatically if missing).

7.3 Dependencies Installation
Use Composer as shown above.

7.4 File Permissions

config/config.php should be set to 600 or 640 (read‑only).

Log directories (if not using database auditing) must be writable.

Upload directories (if any) require proper access controls.

7.5 Network & Security

It is strongly recommended to enable HTTPS (set require_https = true in config).

Configure firewall to open only ports 80/443; restrict SOAP port (7878) to localhost only.

Regularly update PHP and extensions.

8. Usage Workflow Examples

8.1 New User Registration

Visit /register.php, fill in email and password.

The system calls SOAP to create a Battle.net account, generates a game account, and sends an activation email.

User clicks the activation link in the email → account is activated, and user can log in to the web panel.

8.2 Login & Earning Points

Visit /login.php, enter email and password, optionally check “Remember me”.

After login, go to /profile.php to view character list and current points.

In the “Points Centre” section, enter the number of online hours to exchange for points (consumes character’s totaltime).

8.3 Spending Points

Click “Points Shop” to go to /points_shop.php.

Browse items (items, level boost, gold, GM permissions).

Select an item and target character, click “Exchange”.

The system deducts points, performs the corresponding action (sends item mail, updates level, adds gold, etc.), and records the transaction.

8.4 Top‑Up Points

Visit /topup.php, enter the top‑up amount.

Choose a payment method (Stripe/YiPay, etc.).

Complete the payment; the system automatically adds points to the account.

8.5 Security Settings

In /security_settings.php, change password, manage sessions, set security questions.

Security questions serve as an alternative verification method for password recovery.

9. Extension & Customisation

Add a new payment gateway: Add configuration in config.php, implement routing and callback handling in topup.php.

Add new product types: Extend the exchange logic in points_shop.php with new category branches.

Multi‑language: Add language files under languages/ and inherit the Language class.

2FA: The system already reserves the user_2fa table and interface stubs – integrate a TOTP library (e.g., robthree/twofactorauth) to enable it.

10. Maintenance & Monitoring

Log viewing: The audit_logs and login_logs tables provide detailed history; you can build an admin interface to display them.

Periodic cleanup: The system includes AuditLogger::cleanOldLogs($days) to regularly purge old logs.

Database maintenance: Periodically optimise session and token tables by deleting expired records.

Security updates: Keep PHP and Composer dependencies patched.

11. Frequently Asked Questions (FAQ)

Q: Registration fails with “SOAP service unavailable”.
A: Check that worldserver is running, SOAP configuration is correct, and firewall allows port 7878 (preferably only local access).

Q: Activation email not received.
A: Verify SMTP settings and check mail logs; users can use the “Resend activation email” function.

Q: Characters not visible after login.
A: Confirm that characters_database is correctly configured and that the Battle.net account actually has characters.

Q: Item not received after points exchange.
A: Check whether the mail and item_instance tables in the characters database were inserted successfully; ensure the character’s mailbox is not full.

Q: Password reset fails.
A: Ensure SOAP is available and the account exists; if using security questions, verify that the answer hash matches (case‑sensitive).

12. Version & Support

Compatibility: Theoretically compatible with all TrinityCore branches that use the Battle.net account system (minor field name adjustments may be needed).

Technical support: Refer to the TrinityCore official forums or this system’s documentation; troubleshoot using detailed error logs.
